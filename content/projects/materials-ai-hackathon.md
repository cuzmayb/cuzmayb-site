## 문제

소재연구데이터 AI 활용 해커톤 온라인 예선(한국연구재단·한국화학연구원 주관, 데이콘 운영)의 과제였다. 고체전해질의 화학식, 구성 원소와 원자분율, 이동 이온, 측정 온도를 받아 이온전도도(S/m)를 예측한다.

| 항목 | 값 |
|---|---|
| 학습 데이터 | 6,762행, 소재 782개 |
| 평가 데이터 | 2,898행, 소재 370개 |
| 평가 지표 | Log10 MAE. 정답과 예측에 하한 1e-12 S/m를 두고 log10 차이의 평균. 낮을수록 좋다 |
| 순위 | 평가 데이터의 절반(Private)으로만 정한다. 나머지 절반(Public)은 참고용 |
| 기간 | 2026-11-16 10:00 – 11-17 18:00, 하루 제출 10회 |
| 참가 | 35팀. 예선 뒤 10팀 내외가 본선에 간다 |
| 금지 | 외부 데이터, 외부 API, 평가 데이터를 학습이나 통계에 쓰는 것 |

점수 1.0은 예측이 정답과 평균 10배 어긋난다는 뜻이다.

한 소재가 온도만 다른 여러 행으로 들어 있고(소재당 평균 8행), **평가 소재 370개는 학습에 하나도 없다.** 소재 안에서 온도에 따른 변화는 아레니우스 직선이라 쉽다. 행이 4개 이상인 학습 소재 770개에 직선을 맞추면 남는 오차의 중앙값이 0.023이다. 그래서 이 과제는 처음 보는 소재의 전도도 수준을 맞히는 문제가 된다.

## 내가 한 판단과 근거

### 검증 분할부터 정했다

모델보다 먼저 무엇으로 좋아졌다고 판단할지를 정했다. 같은 모델을 세 가지로 나눠 쟀다.

| 검증 분할 | 점수 | 실제 Public과 비교 |
|---|---|---|
| 행 무작위 | 0.37 | 너무 낙관적 |
| 화학식 단위 | 0.70 | 여전히 낙관적 |
| 원소 조합(계열) 단위 | 0.976 | Public 1.0074와 가깝다 |

![같은 모델의 검증 점수를 분할 방식 세 가지로 잰 막대 그림. 행 무작위 0.370, 화학식 단위 0.699, 원소 조합 단위 0.976이고 실제 Public 1.0074가 점선으로 그어져 있다](/images/hackathon-validation-splits.webp "1회차 모델 하나를 세 가지 분할로 잰 검증 점수와 그 모델의 실제 Public 점수. 값은 1회차 학습 로그, 회차 기록, 제출 점수 기록에서 옮겼다.")

근거는 평가 데이터의 구성이다. 평가 행 가운데 원소 조합이 학습에 있는 것은 16.9 %뿐이다. 학습 데이터를 화학식 단위로 나누면 이 비율이 75.8 %가 되어 실제보다 쉬운 검증이 되고, 원소 조합 단위로 나누면 0 %가 된다. 그래서 같은 계열이 학습과 검증에 걸치지 않게 나눴다. 이후 모든 판단은 이 검증으로만 했고, 분할 시드에 따라 0.02 정도 흔들려서 그보다 작은 차이는 개선으로 치지 않았다.

기준선도 쟀다. 전부 중앙값 하나로 찍으면 1.28, 온도와 이동 이온만 쓰면 1.21이다. 조성으로 얻을 수 있는 몫은 그 아래 0.2 – 0.3 정도였다.

### 모델

- **타깃**: log10(전도도). 제출할 때 되돌린다.
- **피처 101개**: 원소 분율, 온도와 1000/T, 이동 이온, 음이온 묶음, 화학식 메모의 공정 단서어 9개(ball milled, annealed 같은 것), 공개 라이선스 원소 임베딩(MEGNet) 16차원.
- **예측**: ExtraTrees와 kNN(k=5)을 학습 조성과의 거리에 따라 섞고, 구조 계열 14종별 아레니우스 기울기 보정을 더했다. 학습 조성에서 먼 행에는 SVR을 0.2 섞었다.
- **최종 파일에 더 들어간 것**: 자기 소재의 직선에서 크게 벗어난 학습 행 139개 제외, 산화물 행에 산화물 전용 모델을 반씩 섞기, 화학 부분집합 5개의 일괄 보정. 보정 폭은 학습 데이터 안쪽 교차검증의 잔차로 정했다.

부스팅 모델은 넣지 않았다. 1회차 피처로 계열 단위 검증을 하면 ExtraTrees 0.974, CatBoost 1.052, LightGBM 1.073이었고, ExtraTrees와 섞어도 0.993으로 단독보다 나빴다.

### 평가 행을 묶는 방법은 뺐다

같은 화학식의 평가 행 여러 개를 묶어 쓰면(예: 그 소재의 측정 온도 범위, 소재별 직선 맞춤) Public이 크게 좋아졌다. 이 방법을 쓴 파일(v9_b)은 Public 0.8373이었다. 평가 입력은 예측에만 쓴다는 규정에 걸린다고 보고 최종 후보에서는 빼 두었고, 묶는 방법을 쓴 파일은 Public 확인용으로만 세 번 냈다.

11-17 오전에 다른 참가자가 대회 게시판에 올린 질문 글에 운영진 답이 달렸다. 평가 행은 하나씩 독립으로 예측해야 한다는 내용이었다. 그 답을 보고 묶는 방법을 전부 닫았다. v9_b는 나중에 보니 Private 1.1776으로 2위 자리였지만 고를 수 없는 파일이었다.

### 재현성과 행 독립을 확인했다

모델 파일을 지우고 다시 학습해도 제출 파일이 바이트 단위로 같다. 새 가상환경에서 제출 코드만 풀어 돌리면 log10 기준 최대 7.0e-13 차이였다. 평가 행을 역순, 무작위 3등분, 한 행씩 넣어도 예측이 같았다.

### Public 점수로 후처리를 정했다

같은 게시판 답에 "Public 점수를 참고한 후처리 파라미터 조정은 허용"이 있었다. 평가 행을 화학 계열 덩어리 7개로 나누고, 덩어리 하나만 log10 +0.3 옮긴 파일을 내서 Public이 어느 쪽을 원하는지 쟀다.

최종 파일은 그 결과로 세 덩어리를 올린 것이다. 황화물의 일부(291행)를 +0.46, 할로겐화물의 일부(185행)를 +0.80, 그 밖의 한 덩어리(246행)를 +0.55 올렸다. 답에 정답을 추정하거나 복원하는 것은 금지라는 단서가 있어서, 덩어리는 화학 계열 수준으로만 두고 소재나 행 단위로 쪼개지 않았다.

이 판단이 틀렸다는 것은 아래 결과에 있다.

## 결과

### 예선 순위

| 제출 | Public | Private | Private 자리 |
|---|---|---|---|
| v1 베이스라인 | 1.0074 | 1.2388 | 9위 |
| v10 (규정 안 Private 최고) | 0.9412 | 1.2066 | 4위 |
| v10a | 0.9273 | 1.2156 | 4위 |
| **최종 (v12 + Public으로 정한 후처리)** | **0.8807** | **1.2412** | **10위 / 34팀** |

"Private 자리"는 그 파일이 최종이었다면 다른 33팀 사이에서 몇 위였는지를 계산한 것이다. 참가 35팀 가운데 Private 리더보드에 오른 것은 34팀이다.

이틀 동안 Public을 1.0074에서 0.8807로 낮췄지만, 최종 파일의 Private은 첫날 베이스라인보다 0.0024 나빴다. 9위와는 0.0020, 11위와는 0.0024 차이였다.

예선 뒤 코드와 모델 파일을 메일로 냈고, 2026-11-20에 본선 진출 통보를 받았다. 진출은 10팀이다. 코드 검증 뒤의 확정 순위는 받지 못했다.

### Public은 Private을 거의 알려 주지 않았다

| 바꾼 것 | 기준 파일 | Public 변화 | Private 변화 |
|---|---|---|---|
| v10a → 최종 (Public으로 정한 세 덩어리 이동) | v10a | −0.0466 | **+0.0256** |
| 황화물 전체 +0.3 | v10a | −0.0069 | +0.0214 |
| 할로겐화물 전체 +0.3 | v10a | −0.0093 | +0.0187 |
| 가넷·NASICON·LLTO +0.3 | p2_b (주) | +0.0189 | −0.0194 |

(주) p2_b는 v12에 황화물 일부와 할로겐화물 일부의 이동만 넣은 파일이다. 위 두 행과 기준이 달라서 크기를 그대로 견줄 수는 없고, 부호만 본다.

![덩어리 하나만 옮긴 탐지 파일 7개의 Public 변화를 가로축, Private 변화를 세로축에 놓은 산점도. 황화물 전체와 할로겐화물 전체는 왼쪽 위, 가넷과 NASICON과 LLTO는 오른쪽 아래에 있다](/images/hackathon-probe-public-private.webp "덩어리 하나만 log10 +0.3 옮긴 탐지 파일 7개의 Public 변화와 Private 변화. 빨간 점은 두 변화의 부호가 반대이고 둘 다 0.005를 넘는 덩어리, 빈 원은 기준 파일이 p2_b인 두 점이다. 값은 예선 종료 뒤 정리한 제출 20건의 점수 기록에서 계산했다.")

Public이 올리라고 한 덩어리는 Private에서 나빠졌고, 건드리지 말라고 한 덩어리는 같은 크기로 좋아졌다. 부호가 뒤집혔다.

리더보드 전체로 봐도 같았다. 34팀의 Public과 Private 순위 상관(Spearman)은 0.155였다. 이 계산에서 우리 팀의 Public은 리더보드에 표시된 0.8373(고르지 않은 v9_b의 점수)이고, 최종 파일의 0.8807로 넣은 값은 아니다. 우리 제출 20건만 보면 −0.002였다. 모든 팀이 Private에서 0.20 – 0.48 나빠졌다. 행을 무작위로 나눴다면 이런 차이가 나기 어려워서, 두 절반이 소재나 계열 단위로 갈렸다고 본다(추정).

### 검증이 맞았던 것

원소 조합 단위 검증이 시드 5개 모두에서 좋다고 한 큰 변경(v6 → v9, 라벨 정리와 산화물 전용 모델)은 Private에서도 살았다. 크기는 검증의 약 40 %였다. v10a → v10도 검증은 좋다고 했고 Public은 나쁘다고 했는데, Private은 검증 편이었다.

## 한계와 다음 단계

### 한계

- 본선 결과는 아직 없다. 본선은 2026-11-26 – 11-27에 한국화학연구원(대전)에서 열릴 예정이고, 이 글은 11-23 기준이다.
- 코드 검증 뒤의 예선 확정 순위는 받지 못했다. 10위는 예선 종료 직후 Private 리더보드의 순위다.
- Public과 Private이 왜 이렇게 다른지는 추정이다. 대회는 분할 방식을 공개하지 않았다.
- v12를 단독으로 내지 않아서, 최종 파일의 +0.0256을 모델 변경분과 후처리분으로 나눌 수 없다. 다만 덩어리 하나씩 옮긴 파일들로 후처리 방향이 손해였다는 것은 확인된다.
- 1위 팀(1.1300)이 무엇을 썼는지는 모른다.

### 다음 단계

본선은 예선과 같은 주제이고, 학습 데이터가 추가되며 평가 데이터가 바뀐다. 모델 성능 50점과 발표 50점으로 평가한다. 예선에서 틀린 판단을 기준으로 바꿀 것을 정했다.

- 최종 파일은 검증으로만 고른다. Public은 제출 형식과 큰 사고를 확인하는 데만 쓴다. Public으로 후처리를 정하는 것은 규정상 허용이었지만, 평가의 절반에 맞춘 것이라 나머지 절반에서 그대로 손해였다.
- 검증이 시드 전부에서 같은 방향이면 Public이 반대로 말해도 검증을 따른다. v10을 Public 때문에 버린 것이 그 반대 사례였다.
- 탐지용 제출에 하루 제출 횟수를 쓰지 않는다. 마지막 날 10건 중 9건이 탐지와 그 결과였다.
